# 星的世界 · UI Design System

## 目标

《星的世界》的界面采用统一的“星际远征”视觉语言：玩家进入游戏时看到的是一套可信、清晰、可长期扩展的沙盒游戏界面，而不是功能控件临时堆叠出的开发工具。

本设计系统覆盖主菜单、地图选择、存档管理、回收站、设置、HUD、引导提示、背包、合成、机器、容器、暂停、死亡、探索日志、更新提示和 F3 诊断。

## 设计原则

1. **玩家任务优先**：当前页面只有一个最明确的主操作；危险操作必须与普通操作区分。
2. **信息层级优先于装饰**：先通过尺寸、间距、位置和对比建立层级，再使用色彩强调。
3. **同一状态只有一种表达**：Primary、Secondary、Ghost、Danger、Selected、Focus 在所有页面共享语义。
4. **真实运行优先**：所有界面必须在 1024×576 与 1280×720 下可用，并通过真实键盘、鼠标和截图验收。
5. **不破坏玩法所有权**：UI 只读取领域事实、发送既有命令，不创建平行状态、Timer 或存档域。

## 视觉方向

### 星空基调

- 深空午夜背景：`#040B13` / `#071421`；
- 玻璃表面：半透明深蓝，保留世界画面和星空层次；
- 冷青交互色：用于焦点、链接、选中状态和运行信息；
- 暖金主操作：用于“开始游戏”“创建世界”“保存并应用”“重生”等单一主任务；
- 红色危险语义：只用于删除、永久清理、失败和严重状态。

主菜单的程序化背景包含星云、星座、轨道、卫星与行星，不依赖外部图片资产，因此在 Release 中保持确定性和可测试性。

### 8pt 间距体系

```text
2 / 4 / 8 / 12 / 16 / 24 / 32 / 40 px
```

常规控件之间使用 8 或 12px；卡片与页面区域使用 16 或 24px；主菜单 Hero 与 Command Deck 使用 40px。不得在新页面随意引入无法解释的间距值。

### 字体层级

```text
Display   56px  品牌主标题
Title     30px  页面标题
Section   20px  区域标题
Body      17px  正文与主控件
Small     15px  说明文本
Caption   14px  状态、指标与辅助信息
Micro     12px  快捷键、槽位编号
```

所有正文必须在深色表面上保持高对比。主文字与核心表面目标对比度不低于 7:1。

## 组件语义

### 按钮

- `PrimaryButton`：当前页面唯一主任务；暖金填充。
- `SecondaryButton`：重要但可替代的操作；冷青表面。
- `GhostButton`：返回、关闭、低优先级工具。
- `DangerButton`：删除、退出或不可逆操作。
- `MenuPrimaryButton`：主菜单“开始游戏”。
- `CardButton` / `SelectedCardButton`：地图和存档卡片。
- `InventorySlot` / `InventorySlotSelected` / `InventorySlotSwap`：物品槽位三种稳定状态。

所有可操作按钮必须具备 Hover、Pressed、Disabled 和键盘焦点状态。焦点使用 2px 高对比冷青边框，不能只依赖颜色轻微变化。

### 面板

- `GlassPanel`：轻量信息卡；
- `ElevatedPanel`：地图、设置、存档等完整页面；
- `CommandPanel`：主菜单远征指挥台；
- `CardPanel`：内容分组；
- `InsetPanel`：列表、网格和可滚动内容；
- `HudPanel`：游戏内非阻塞信息；
- `ModalPanel`：暂停、死亡和更新提示；
- `DiagnosticsBackdrop` / `DiagnosticsCard`：F3 只读诊断。

## 页面架构

### 主菜单

主菜单不再使用“居中大面板 + 同权重按钮”结构，而是：

```text
品牌 Hero / 世界观 / 能力摘要  |  远征指挥台
```

左侧解释游戏是什么，右侧承担开始、地图、存档、设置、更新和退出。暖金“开始游戏”是唯一主操作，退出保持危险语义。

### 地图、设置与存档

所有管理页统一为：

```text
Eyebrow + 页面标题 + 说明
工具区 / 查询区
主内容卡片或列表
状态区
固定操作区
```

设置页的四个分组卡片进入单一滚动区，状态和“保存并应用”始终固定；存档浏览器保持 24 行虚拟化，不因视觉升级创建无限控件。

### 游戏内 HUD

HUD 的视觉优先级为：

1. 中央准星和当前交互；
2. 底部快捷栏与当前物品；
3. 左上生命、饥饿与时间；
4. 右上区域威胁与来袭攻击；
5. 教学、Toast 和临时反馈。

HUD、引导和弹窗必须互不遮挡。阻塞弹窗统一使用一个暗幕，打开后暂停或切换输入上下文，关闭后恢复游戏输入。

### 功能工作区

背包、合成、容器、机器和探索日志使用一致的“标题 + 状态 + 卡片工作区”结构。列表和网格必须拥有自己的滚动或固定预算，不能依赖整个弹窗越界。

### F3

F3 是只读运行诊断中心：左栏显示帧、Chunk、输入与玩家；右栏显示领域预算、存档、目录和检查点时间线。所有 Control 保持鼠标穿透，F3 不抢夺游戏输入。

## 分辨率合同

### 1024×576

- 所有主页面、弹窗和工作区必须完整位于安全区；
- 设置、探索日志和长列表使用内部滚动；
- 标题可降级到 48px，但按钮、焦点和可点击面积不得缩小到不可用；
- HUD 卡片不得与快捷栏、交互提示或教学卡重叠。

### 1280×720

- 使用完整 Hero、双栏管理页和双栏 F3；
- 保留 18px 以上安全边距；
- 真实截图必须验证主菜单、地图、设置、存档、HUD、暂停、背包、合成、探索日志和诊断共十个界面。

## 交互与可访问性

- 主操作最小高度 52px，普通操作 44px，紧凑工具 36px；
- 所有按钮支持键盘焦点；
- 危险操作必须二次确认且使用明确文案；
- 状态不能只靠颜色表达，必须有文字或图标；
- F3、HUD 和引导中非交互 Control 必须保持 `MOUSE_FILTER_IGNORE`；
- 动画只使用短时淡入，不移动容器最终布局，不影响自动化测量。

## 测试合同

永久门禁包括：

1. 静态设计系统合同；
2. Theme 变体与颜色对比单元回归；
3. 主菜单、地图、设置、存档和弹窗的 1024×576 / 1280×720 布局回归；
4. 真实鼠标点击和真实键盘快捷键；
5. 十张真实桌面截图、JSON、stdout/stderr；
6. 现有 UI、输入、保存、自动保存、探索日志和 F3 相邻回归；
7. 完整桌面矩阵；
8. Windows Release 实际导出、启动与退出资源检查。
