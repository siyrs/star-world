# Product Requirement

## Background
- 《星的世界》需要一次真实 Windows 商业发布前的端到端体验、稳定性、性能和内容覆盖闭环。工作必须在当前仓库和当前电脑上完成，并保留可复现证据。

## User Value
- 玩家能够从新建游戏开始，稳定进入、探索和完成全部正式内容，并可信地保存、退出、重进和恢复。
- 发布负责人能够依据构建、运行日志、截图、性能采样、地图覆盖矩阵和独立回归证据作出发布决策。

## Goals
- 发现全部可加载地图、任务、模式、角色、物品、交互、传送、存档和设置内容。
- 实际构建、运行和操作游戏，跑通所有有通关条件的正式地图与关键流程。
- 修复实际复现的 P0/P1 问题，合理处理 P2/P3 体验问题，并为修复建立回归证据。
- 建立与发布逻辑隔离的自动化巡检、异常检测、性能采样和证据持久化能力。
- 在独立分支以小而清晰的提交交付，不发布、不强推、不覆盖用户修改。

## In Scope
- Windows Desktop Godot 4 项目的源码、资源、场景、数据、测试、QA 工具和发布构建。
- 全地图进入/重入/通关、任务、交互、边界、碰撞、水域、水下、高空、地下、隐藏区域、存读档、死亡复活、地图切换、设置、暂停与退出。
- 正常与极端输入、长稳、错误日志、CPU/GPU/内存/帧率/加载/GC 数据。
- 发现问题后的根因定位、代码或资源修复、自动化回归、重建和独立 QA 复测。

## Out of Scope
- 未经授权的正式商店发布、正式服务器操作、强制推送、标签或 GitHub Release。
- 付费资源、账号、许可证或当前电脑不存在的外部资产；若真实阻塞则保留证据并记录。
- 用跳过任务、直接标记通关、删除玩法或取消碰撞伪造通过。

## User Stories
| Role | Need | Value |
|---|---|---|
| 玩家 | 能正常发现、进入并完成全部正式内容 | 游戏不是只能完成教程的空壳 |
| 玩家 | 在碰撞、水域、地图边界和极端操作下可恢复 | 避免永久卡死、掉图和状态污染 |
| 玩家 | 存档、死亡、重进和地图切换保持正确状态 | 长期游玩进度可信 |
| 发布负责人 | 获得实测覆盖、性能和缺陷闭环证据 | 能作出可靠发布决定 |

## Priority
- P0：启动/主要地图/通关/存档/永久卡死/崩溃/黑白屏/关键任务。
- P1：高频卡顿、水下/碰撞/相机/任务状态/关键 UI/AI 等严重体验问题。
- P2/P3：在 P0/P1 清零并完成地图覆盖后继续修复与打磨。

## Risks and Dependencies
- Windows 图形 UI 和输入自动化的可观测性需以截图、日志和游戏内状态共同佐证。
- 内容规模、动态生成地图或隐藏入口需要从代码、配置、菜单与可加载资源交叉发现。
- 性能数字受硬件、VSync、窗口状态和采样工具影响，必须固定场景和参数。
- 任务可能跨多轮；`qa/session-state.md` 是唯一恢复入口，重要步骤后必须更新。
