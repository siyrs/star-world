# 有界数据驱动远程战斗合同

## 目标

第一版远程战斗不是独立小游戏，也不是另一套伤害系统。它把“制作猎弓与箭矢、装备、长按蓄力、松开发射、真实飞行、命中结算、耐久与弹药、保存重载”接入现有角色、背包、装备、战斗、输入、UI 和存档边界。

## 权威所有者

```text
data/ranged_combat.json
  └─ RangedWeaponRegistry       数据与范围

CharacterProgressionPlayer
  └─ 鼠标左键 / 手柄主扳机      同一蓄力意图

RangedCombatService
  ├─ 蓄力与冷却                 瞬态
  ├─ 原子消耗一支箭
  ├─ 消耗主手猎弓耐久
  └─ ProjectileRuntimeService   单一有界飞行运行时

ProjectileRuntimeService
  └─ CombatService.resolve_projectile_hit()
       └─ 目标实时防御、伤害、击退、受击硬直和击败语义
```

`CombatService` 继续是唯一伤害结算入口。投射物不会直接修改目标生命，也不会复制近战伤害计算器。

## 数据扩展

`ItemRegistry` 和 `CraftingService` 先把基础文件与扩展文件加载到临时字典，全部通过后一次替换正式注册表：

- 任一文件缺失或结构错误时不提交部分数据；
- 基础与扩展之间的重复 item / recipe ID 直接拒绝；
- 自定义测试注册表不会隐式加载生产扩展；
- 猎弓继续使用现有 `main_hand` 装备槽；
- 箭矢使用现有背包堆叠与原子事务。

## 蓄力事务

```text
按下主动作
→ 验证猎弓、箭矢、冷却和 64 投射物容量
→ 进入 charging

松开主动作
→ 低于 minimum_draw_ratio：拒绝，不消耗
→ 武器改变 / 无箭 / 满容量：拒绝，不消耗
→ 原子移除 1 arrow
→ 创建投射物成功
→ 消耗 1 主手耐久
→ 进入有界 cooldown
```

投射物创建异常失败时，箭矢会回滚。取消输入、打开界面、世界切换或运动重置只取消蓄力，不发射、不消耗。

## 投射物预算

- 全局最多 64 支活动箭；
- 只有一个 `ProjectileRuntimeService._physics_process()`；
- 每支箭每物理帧最多一次线段射线，防止高速穿透；
- 最大速度、飞行距离和寿命由注册表硬限制；
- 命中、超时、世界切换和 shutdown 都确定性释放视觉节点；
- 不创建每箭 Timer、线程、第二保存域或全世界扫描。

## 持久化边界

持久化：

- 背包中的箭矢数量；
- `equipment.main_hand` 中猎弓和耐久。

不持久化：

- 蓄力秒数；
- 冷却剩余；
- 飞行中的箭；
- 投射物计数器和诊断；
- 最近命中 UI。

因此不修改 `world.json` schema，也不需要迁移旧世界。

## 玩家反馈

共享战斗 Overlay 显示：

- 猎弓蓄力百分比；
- 冷却恢复百分比；
- 当前箭矢数量；
- 命中、击败、无箭、蓄力不足和容量上限。

阻塞 UI 打开时隐藏战斗反馈，1024×576 下保持在视口内。

## 验收

必须同时通过：

1. 数据、重复 ID 和原子配方回归；
2. 真实物理射线、目标防御、单次伤害、箭矢与耐久事务；
3. 64 支容量、暂停与世界清理；
4. 正式 `game.tscn` 的真实鼠标长按/松开；
5. 真实手柄右扳机长按/松开；
6. 两张截图、JSON、stdout/stderr；
7. 保存、返回菜单、重载后的箭矢与耐久；
8. 权威 Runtime、完整桌面矩阵与 Windows Release。
