# 战斗反馈、遭遇强度与弹药经济

## 目标

Iteration 57 完成 Iteration 56 路线图中剩余的可自动化战斗任务：方向受击反馈、遭遇强度设置、弹药制造/奖励再平衡，以及 3,600 秒混合战斗长稳。实现继续复用现有 Combat、Encounter、Inventory、Crafting 与 Save 权威边界，不建立平行系统。

## 方向受击的权威数据链

`CombatService.incoming_damage_resolved` 是唯一的受击反馈事件。近战与敌对投射物在结算时携带攻击者位置；玩家在同一次权威结算中计算：

- 最终伤害；
- 护甲吸收；
- 前、右、后、左四方向；
- 来源位置是否可用；
- 近战、深渊弹或环境来源。

HUD 只消费该结果，不重新计算伤害。方向脉冲使用固定四槽池，禁止按受击次数创建无限控件。玩家可关闭视觉方向脉冲，但伤害数字、方向文字和护甲吸收文字仍保留。相机冲击强度为本地设置，范围固定为 0.0–1.5。

## 遭遇强度

`data/encounter_intensity_profiles.json` 使用 schema version 1，只有三档：

| ID | 显示名 | 冷却倍率 | 危险压力倍率 |
|---|---|---:|---:|
| `casual` | 休闲 | 1.35 | 0.75 |
| `standard` | 标准 | 1.00 | 1.00 |
| `high_risk` | 高危 | 0.75 | 1.25 |

强度只缩放 Encounter 冷却和危险预算。它不改变：

- 正式 Encounter profile ID；
- 敌人种类、角色或编组；
- 奖励归属；
- 世界存档进度；
- 活动遭遇或成员的持久化结构。

损坏、未知或非有限设置回退到 `standard`。该值只进入现有本地 settings 白名单，运行中切换后由 ServiceHub 向 Encounter Director、玩家相机与 HUD 传播。

## 弹药经济再平衡

正式 Encounter 奖励不再直接发放成品弹药。允许的奖励物品仅为：

- 燧石 `flint`；
- 火药 `gunpowder`。

`EncounterRewardRegistry` 在数据加载时拒绝箭矢、轻型弹和霰弹；`EncounterRewardService` 在首次发放、待领取、自动重试和事务 additions 构造时再次拒绝成品弹药。这样即使旧 pending、测试注入或异常数据绕过注册表，也不能写入背包。

为形成真实闭环，正式箭矢配方从“木棍 + 羽毛 + 石头”改为“木棍 + 羽毛 + 燧石”，一次仍产出 4 支箭。通用石头不再代替燧石。枪械弹药仍由现有制造与资源链路负责，遭遇只提高火药输入，不直接制造完成子弹。

## 有界长稳

确定性混合战斗夹具覆盖恰好 3,600 秒，固定包含：

- 2 名深渊射手；
- 4 只僵尸；
- 1 名深渊重击者；
- 持续玩家开火与敌对攻击；
- 六次暂停窗口；
- 三次 JSON 保存/重载边界；
- 80 次正式 Encounter 奖励；
- 弹丸、遭遇、成员、方向脉冲的高水位；
- 返回菜单后的显式清理。

该测试是可重复的逻辑时长证明，不冒充真实 Windows 目标硬件墙钟长稳。
