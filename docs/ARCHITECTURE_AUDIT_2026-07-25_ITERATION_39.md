# Architecture Audit · 2026-07-25 · Iteration 39

## 范围

上一轮已经把存档浏览器节点数量限制为固定 24 行，并允许目录积压最多自动整理 6 轮。本轮继续审计刷新后的内存路径和大目录定位体验。

## 发现

### 1. 刷新仍深拷贝全部 metadata

旧实现执行：

```text
_worlds = raw_worlds.duplicate(true)
```

虽然 metadata 只是目录白名单投影，面板仍对每个 Dictionary 做全量深拷贝。随着世界数量增长，这会增加分配、字符串复制和垃圾回收压力。

面板从不修改这些 Dictionary，因此深拷贝没有提供有效隔离。

### 2. 选择与 metadata 查找仍为线性扫描

旧 `_metadata_for_world()` 和 `_contains_world()` 会逐项扫描 `_worlds`。单次成本不高，但选择、刷新、查询和安全校验叠加后，仍会重复执行 O(n) 查找。

稳定 world ID 已经存在，正确结构应是直接的内存索引。

### 3. 大目录只能逐页人工查找

固定 24 行解决了节点增长，却没有解决 256 个或更多世界下的定位成本。玩家需要逐页寻找名称、地图或 Seed，分页从性能方案变成操作负担。

### 4. 逐键输入不应触发全目录匹配

把搜索直接绑定到 `text_changed` 会在每次输入时执行 O(n) 过滤与 O(n log n) 排序。大目录和输入法组合文本会放大该成本。

本轮选择 Enter/按钮显式应用，不增加 Timer，也不建立新的异步调度域。

### 5. 隐藏选择存在误删风险

搜索前选择一个世界，搜索后若该世界不可见但选择仍保留，“删除所选”可能删除玩家当前看不到的记录。

## 决策

### 只读浅引用与直接索引

刷新后只保留只读浅引用并建立：

```text
world_id → metadata
```

- 不再深拷贝；
- 重复 ID 去重；
- metadata 查询改为 Dictionary 直接访问；
- UI 仍不得修改领域 Dictionary。

### 纯查询策略

新增 `SaveBrowserQueryPolicy`：

- 查询最长 64 字符；
- 最多 8 个唯一 token；
- 搜索名称、ID、地图和 Seed；
- 支持最近更新、名称和存档大小排序；
- 所有排序以稳定 world ID 打破平局；
- 不访问文件、服务或 payload。

### 查询零磁盘扫描

查询结果只保存 world ID 列表，继续复用固定 24 行。搜索、排序和分页不会调用 `list_worlds()`，不会推进任何恢复或目录预算。

### 隐藏选择清空

查询重建后，如果当前选择不在匹配 world ID 集合中，立即清空选择，避免不可见删除。

## 真实验收

### 纯策略

使用 256 条合成 metadata 验证：

- 查询长度和 token 上限；
- 名称、ID、地图、Seed 搜索；
- 三种排序；
- 重复 ID 去重；
- 稳定 tie-break。

### 面板回归

Fake SaveService 提供 256 条记录：

- 只执行一次真实列表调用；
- 固定 24 行、11 页；
- 查询和排序零服务调用；
- 逐键输入不自动应用；
- 隐藏选择清空；
- 刷新只重建一次索引且不创建新行。

### 真实桌面

正式 GameScene 创建 256 个真实世界：

- 256/256 sidecar 命中；
- 11 页固定行池；
- Gamma 64 项、snowfield 51 项、Seed 单项命中；
- 查询和分页期间 catalog `list_count` 不变；
- 截图、JSON、Primary 逐字节验证；
- 稳态零完整读取和零目录写入。

### 完整门禁

最终候选必须继续通过：

- 虚拟化、目录暂存、权威读取、目录重建和多世界恢复；
- Save Recovery、World Catalog、统一健康和 Runtime Stability；
- 总 Runtime 与三轮 lifecycle soak；
- 完整真实桌面矩阵；
- Windows Release 实际导出、启动和 Artifact。

## 结论

本轮把存档浏览器从“节点数量有界”推进为“内存访问和玩家定位也有界”：刷新不再深拷贝，metadata 不再线性扫描，搜索不会逐键触发全目录工作，隐藏选择不会造成误删。大目录仍保持 `world.json` 唯一权威，所有查询能力只是可重建的内存投影。
