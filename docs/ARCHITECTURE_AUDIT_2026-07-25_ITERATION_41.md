# Architecture Audit · 2026-07-25 · Iteration 41

## 范围

本轮在受保护删除、32 条物理容量和最近一次 Undo 基础上，审计长期回收站管理、损坏条目和容量释放路径。

## 发现

### 1. 最近一次 Undo 不是完整管理能力

已有“撤销删除”只能恢复最新有效条目。玩家无法查看或恢复更早世界。多个重要世界连续删除后，只能按时间逆序逐个恢复，体验和可控性不足。

### 2. 32 条容量存在玩家级死锁

回收站满时新删除被正确拒绝，但当前玩家 UI 没有永久清理入口。除非恢复所有旧世界，否则无法释放容量。

这会把安全硬上限变成长期不可用状态。

### 3. 损坏 Manifest 占容量但无法处理

物理目录必须计入容量，避免损坏 Manifest 绕过 32 条上限。但旧接口 `list_trashed_worlds()` 只返回有效条目，`purge_trashed_world()` 也拒绝无效 Manifest。

因此一个损坏目录可能永久占用容量，同时在 UI 中不可见。

### 4. 永久清理不能复用活动世界删除

管理回收站需要删除 Trash 目录，但绝不能调用 `SaveService.delete_world()`：

- 活动世界和回收站是不同状态域；
- world ID 可能为空或 Manifest 损坏；
- 路径必须以安全 Trash ID 为唯一输入；
- 玩家操作必须二次确认。

### 5. 秒级/普通微秒值仍需严格单调

系统时钟可能在快速文件操作中返回相同精度值。仅保存 `now_usec` 仍可能出现相同时间。

新删除时间必须使用：

```text
max(now_usec, previous_latest_usec + 1)
```

以保证跨会话和低分辨率时钟下的严格顺序。

### 6. 回收站 UI 仍必须保持有界

虽然回收站容量只有 32，但动态为每个条目创建控件会重复旧存档浏览器问题。应复用现有 24 行虚拟化合同，形成最多两页。

## 决策

### 服务投影

新增 `list_trash_slots(32)`：

- 有效条目可恢复、可清理；
- 损坏条目不可恢复、可清理；
- 不安全目录不可恢复、不可清理；
- 最多扫描 64 个异常物理目录；
- 最多向 UI 返回 32 个槽位。

### 明确清理端口

新增 `purge_trash_slot(trash_id)`，只接受安全 Trash ID，并只删除 `user://world_trash/<trash_id>`。

保留 `purge_trashed_world()` 的有效 Manifest 兼容语义，它内部委托给槽位清理。

### 管理页

新增 `SaveTrashManagerPanel`：

- 固定 24 行；
- 最多两页；
- 指定恢复；
- 损坏条目明确标记；
- 永久清理二次确认；
- 选择、翻页、刷新或离开页面取消确认；
- 隐藏管理页零预热扫描，首次打开才读取目录；
- 翻页零额外扫描。

### 生产接入

`ProtectedSaveBrowserPanel` 增加“管理回收站”，管理页作为覆盖层复用当前服务，不新增顶层 MainMenu 状态机。

## 真实验收设计

### 服务

- 快速删除四个真实世界；
- 重建 Service 模拟应用重启；
- 验证严格单调时间与最新有效 Undo；
- 损坏一个 Manifest；
- 精确恢复较旧条目；
- 精确清理损坏物理目录；
- 文件逐字节和稀疏修改完整性。

### UI

- Fake Service 提供 31 有效 + 1 损坏；
- 固定 24 行、两页；
- 翻页零扫描；
- 损坏恢复禁用；
- 永久清理两次点击；
- 选择变化取消确认；
- 指定恢复较旧条目；
- 活动世界永久删除调用为 0。

### 真实桌面

- 33 个真实世界；
- 回收站 32/32；
- 第 33 个删除被拒绝；
- 31 有效 + 1 损坏；
- 指定恢复后容量 31；
- 二次确认清理损坏条目后容量 30；
- 原第 33 个世界随后成功进入回收站；
- 最终 31 个有效槽位、0 损坏；
- 恢复世界可在活动浏览器直接搜索。

### 全量门禁

最终固定 SHA 必须通过：

- 静态合同、严格导入；
- 服务、UI、真实桌面专项；
- 保护删除、索引/虚拟化浏览器；
- 目录暂存、权威读取、目录重建、多世界恢复；
- Save Recovery、World Catalog、统一健康；
- Runtime 与三轮 lifecycle soak；
- 完整真实桌面矩阵；
- Windows Release 实际导出和启动。

## 结论

本轮把回收站从“最近一次可撤销”推进为“指定恢复、损坏 Manifest 可治理、容量可释放、永久清理二次确认和固定 24 行”的长期可用管理闭环，同时保持玩家活动世界永久删除调用为 0，并继续要求真实桌面与 Windows Release 验收。
