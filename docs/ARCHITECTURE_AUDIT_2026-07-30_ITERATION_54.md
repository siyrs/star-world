# Architecture Audit · 2026-07-30 · Iteration 54

## 审计目标

在玩家枪械合入后，继续推进真实敌对远程作战，并清理上一轮暴露的验收与架构债务。

审计问题：

- 上一轮桌面测试为何运行 20 分钟后失败；
- 新远程敌人是否会复制玩家枪械或绕过 CombatService；
- 敌对投射物是否会与玩家箭矢争抢容量；
- 远程敌人是否瞬发、不可躲；
- 掩体决策是否需要昂贵的导航扫描；
- 多敌人的伤害压力是否被全局冷却错误吞掉；
- 敌对 profile 加载失败是否会公开半份注册表；
- 扩展物品是否真正进入全局数据闭包。

## 发现 1：上一轮桌面失败是测试生命周期错误

枪械真实点击已经进入生产路径，但目标在命中后可能被击败并 `queue_free()`。测试随后在异步等待结束后直接执行：

```gdscript
float(target.get("health"))
```

目标释放后触发 `previously freed instance`，测试无法进入清理，最终达到 1,200,000 ms 超时。

修复：

- 保存稳定 `target_id`；
- 使用 `WeakRef`；
- 以 CombatService 的 `accepted/defeated` 结果为权威；
- 只有 WeakRef 仍有效时才读取目标生命；
- 被击败并卸载被视为合法成功路径。

## 发现 2：敌对远程攻击不能复用 hitscan

玩家枪械使用 hitscan 是即时操作反馈；敌人若同样瞬发，玩家无法通过移动或掩体反应。

决策：

- 敌人显示 1.1 秒瞄准光束；
- 使用真实物理投射物；
- 方块和实体可以拦截；
- 视线丢失取消攻击；
- 命中仍进入 CombatService。

## 发现 3：投射物边界不应只依赖上游 profile

原 `ProjectileRuntimeService` 对速度、距离和寿命主要依赖注册表约束。直接调用服务时仍可提交越界请求。

修复：运行时增加最后一道硬验证：

- 速度 ≤ 96；
- 距离 ≤ 256；
- 寿命 ≤ 12 秒；
- 重力 ≤ 64；
- 碰撞掩码必须有效；
- 无效请求不创建节点。

## 发现 4：玩家与敌对投射物需要独立容量池

若共用一个 64 容量池，敌人密集射击可能阻止玩家发箭；反之玩家箭雨也可能使敌人停止攻击。

决策：

- 玩家 `RangedCombatService` 保持 64 容量；
- ServiceHub 新增 24 容量敌对共享运行时；
- 两者复用同一实现，但生命周期和预算独立；
- 两个池都不进入存档。

## 发现 5：全局敌对受击冷却使多敌人压力失真

旧玩家状态只有：

```text
_hostile_damage_cooldown_remaining
```

任意僵尸命中后，其他敌人也会被全局屏蔽约 4.5 秒。多敌人只是视觉数量，没有真实协同压力。

修复：

- 新增最多 32 个按攻击者 cooldown；
- key 优先使用 instance ID；
- 旧来源调用使用 source ID 兼容；
- 同一攻击者重复命中拒绝；
- 不同攻击者可立即命中；
- 容量满时淘汰剩余时间最短条目；
- 旧标量仅作为最大剩余时间诊断投影。

## 发现 6：敌对 profile 加载不是原子的

原注册表先清空 `_profiles`，随后逐条写入。若后半段出现错误，调用者会观察到不完整状态。

修复：

```text
parse
→ normalize into staged
→ validate every profile
→ any error: preserve previous complete registry
→ all valid: _profiles = staged
```

## 发现 7：扩展内容未进入全局引用闭包

核心 `validate_data.ps1` 只读取基础 `items.json` 和 `recipes.json`。弓箭与枪械依赖各自专项 validator，生物掉落也只统计数量，不验证 item ID。

修复：

- 合并基础、弓箭和枪械 items/recipes；
- 检查跨文件重复 ID；
- 所有机器、采集、作物和生物掉落共享同一个 item ID 集；
- 验证每个生物数值与掉落区间；
- 深渊射手掉落的 `gunpowder` 由核心门禁确认存在。

## 发现 8：掩体不能依赖全图导航扫描

首版仅需要局部战术行为，不应引入导航洪泛或每帧世界搜索。

决策：

- 视线每 0.16 秒缓存一次；
- 冷却时每 0.8 秒最多尝试一次掩体；
- 最多 6 个候选；
- 每个候选最多地面、通路、遮挡三条射线；
- 无 `get_nodes_in_group()` 热路径；
- 找不到掩体时退化为有界侧移。

## 最终架构边界

```text
配置：严格、原子、只读
策略：纯 RefCounted
AI：持有少量瞬态标量和缓存
投射物：单共享物理循环
伤害：CombatService + 玩家权威入口
存档：不包含投射物、视线、掩体或 cooldown map
验收：WeakRef 安全覆盖死亡与卸载
```
