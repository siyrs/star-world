# 架构审计：Iteration 46 — 数据驱动世界地标

## 审计基线

- 主分支：`master`
- 基线提交：`0823c6cb0b2ec27326f9fc54070aa445456d67ca`
- 上一轮：K3 体验层工程化收敛、三档生存、相机与粒子预算、品牌恢复。

## 结论

K3 增加的地表装饰明显改善了世界观感，但实现仍集中在 `world_generator.gd` 的地图 `match` 分支中。继续添加遗迹、战利品、任务入口或新地图会扩大生成器职责，并让 Seed 兼容只能依赖人工维护。

本轮不增加新的世界内容数量，而是先建立可扩展且兼容旧世界的数据驱动 POI/装饰基础。

## P0

### 地表装饰与遗迹硬编码在核心生成器

影响：

- 地图内容、概率、结构预算和 Seed Salt 分散在生成器方法内；
- 每新增一种装饰都需要修改核心地形代码；
- 无独立 Schema、字段白名单或规则预算；
- 难以证明重构前后旧 Seed 完全一致。

处理：

- 新增 `data/world_decoration_profiles.json`；
- 新增严格 `WorldDecorationRegistry`；
- 新增纯 `WorldDecorationPolicy`；
- 生成器只提供地形上下文和权威 Hash；
- 删除 `_cactus_height`、`_ruin_site_center`、`_ruin_pillar_height` 和 `_ruin_debris_here` 硬编码助手；
- 三 Seed、五地图、多个地表高度逐点对比旧算法。

## P1

### 地标能力对玩家不可见

影响：地图选择只显示资源特点，玩家无法知道荒漠真的存在遗迹、天空岛装饰受岛体强度约束或深渊有低频晶体。

处理：地图简报新增“地表地标”摘要，与资源特点共享权威数据源。

### POI 缺少有界诊断

影响：后续加入战利品和任务入口时，无法确认结构 Cell、激活 Roll、中心与规则预算。

处理：生成器新增只读 POI Snapshot，暴露 Profile、规则数量、Cell、激活、Roll 和中心，不扫描世界、不进入存档。

## P2

### 当前 POI 仍只有荒漠遗迹一种结构类型

本轮不扩展新结构，避免在没有战利品、任务与结构完整性合同前堆内容。下一阶段可基于同一注册表增加：

- 冰原冰刺或冻树群；
- 天空遗迹；
- 深渊晶体簇；
- 结构战利品表和一次性领取状态；
- 探索日志与任务入口。

前提是先定义持久化、重复领取、Chunk 卸载和旧世界迁移合同。

## 验收矩阵

| 层级 | 内容 |
|---|---|
| 静态 | 五地图一一对应、16 规则预算、字段/方块/概率/Cell 校验、旧硬编码移除 |
| Headless | 非法注册拒绝、三 Seed 五地图逐点兼容、POI 中心与断柱对应、地图简报 |
| 桌面 | 真实鼠标选图、地标摘要、正式 VoxelWorld、3×3 Chunk、真实遗迹截图与 JSON |
| 相邻 | 资源分布、UI Design、Integration |
| 权威 | 32 阶段 Runtime、完整桌面矩阵、UI 十屏、Windows Release |

## 不接受的实现方向

- 不把 POI 结果写入每个 Chunk 或 `world.json`；
- 不为每个结构创建 Timer；
- 不在世界启动时扫描全部 Cell；
- 不修改旧 Hash、Salt 或阈值；
- 不在本轮引入战利品、Boss、XP 或任务状态。
