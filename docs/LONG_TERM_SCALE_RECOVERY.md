# 长期规模与恢复合同

## 目标

Iteration 58 将“单项预算存在”提升为“跨会话、跨领域、长周期仍然收敛”的工程合同。它不新增第二套存档、第二套掉落循环或新的 UI 状态，而是复用现有权威服务并补齐崩溃窗口、长期淘汰和真实桌面证据。

## 1. World 与 Catalog 跨文件事务

`world.json` 始终是权威状态，`catalog.json` 只是可重建 sidecar。保存事务遵守：

1. 在替换 `world.json` 前创建 `catalog.pending`；
2. 原子写入权威 world；
3. 写入与该 world 对应的 catalog；
4. 只有 catalog 成功后才移除 pending；
5. world 写入失败时移除 pending，不制造虚假失效；
6. 重启后的目录扫描看到 pending 时必须拒绝旧 catalog、回读权威 world、按既有预算重建 sidecar，并清除 pending。

该标记解决“新旧 world 文件字节数相同、但崩溃发生在 world 成功与 catalog 成功之间”时旧 sidecar 可能被误接受的问题。标记不进入 `world.json`，不改变存档 schema，也不参与玩法状态。

## 2. 既有硬预算保持不变

长期资格不得放宽现有边界：

- 每次目录扫描主文件修复最多 8；
- 权威 world 读取最多 32；
- sidecar 写入/重建最多 16；
- 进程内暂存 catalog 最多 64；
- 存档浏览器活动行最多 24；
- 查询最多 64 字符和 8 token；
- 回收站物理条目最多 32；
- 检查点可见历史最多 12；
- 自动保存只能有一个 pending；
- 物理掉落共享运行时最多 128 节点；
- 结构完整性保持一个可暂停、事件驱动的批处理运行时。

## 3. 二十四小时自动保存与检查点

确定性资格夹具模拟 24 小时活动时间：

- 5 分钟窗口共 288 个；
- 三次失败突发，每次依次进入 15、60、300 秒退避；
- 每个窗口最终只提交一次成功自动保存；
- 每四小时插入一次手动保存，共 6 次；
- 失败恢复后连续失败压力归零；
- 检查点历史持续保持 12 条，旧事件逐条精确淘汰；
- 原因累计计数不随显示历史淘汰而丢失；
- 五个世界的历史可保留，但当前世界本次进入只显示进入边界后的自身事件；
- 显式会话重置从空序列重新收敛。

自动保存调度、失败压力和检查点历史继续是瞬态诊断，不写入 `world.json`。

## 4. 结构与掉落长期压力

资格夹具连续执行：

- 24 轮门/梯结构支撑移除、去重、单次 nested cleanup 和节点释放；
- 5 轮满 128 节点掉落生成、共享步进、统一过期、注销和运行时销毁；
- 每轮结束必须回到零追踪节点、零临时根节点；
- 峰值不得超过既有硬容量；
- 相邻回归继续覆盖玻璃板/栅栏连接、世界修改批次和 Chunk 热返回缓存。

## 5. 超宽屏、高 DPI 与控制器焦点

CI 桌面证据使用：

- 3440×1440 物理窗口；
- 1720×720 逻辑画布，即 2× 逻辑缩放；
- 真实 Joypad D-pad、A、B 输入；
- 主菜单和设置工作区焦点移动、接受、取消；
- 所有可见按钮必须位于逻辑可视区域；
- 聚焦控件必须消费共享高对比 focus style；
- 输出 PNG 与 JSON 焦点路线报告。

这属于自动化布局和输入证据，不替代真实设备上的人工 E4-H 体验签字。

## 6. 非目标与发布边界

本迭代不引入管道、电网、跨 Chunk 物流、新 Boss 或新的平行持久化领域。商业发布仍为 **HOLD**，直到完成：

- 独立 E4-H 体验签字；
- 最低与推荐真实目标硬件资格；
- 最终发布包在目标硬件上的严格 7,200 秒 soak。
