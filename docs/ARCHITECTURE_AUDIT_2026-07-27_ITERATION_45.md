# 架构审计：Iteration 45 — K3 体验层收敛

## 审计基线

- 主分支：`master`
- 基线提交：`d83ada3c5c6eb8abe18cff9cf06deebcc8d3e6b0`
- 目标：复审 K3 已直接合入的像素 UI、相机、音效、碎屑、生存调参与世界装饰，并补齐工程门禁。

## 结论

K3 正确识别了“工程完整、体验反馈不足”的核心问题。世界装饰、程序化音效、镜头语言、受击反馈和像素化方向应保留。但新增实现没有完全遵守本项目长期形成的策略、预算、生命周期与验证纪律。

## P0

### 新体验层缺少固定候选的完整 CI 证据

K3 变更直接进入 `master`，基线提交没有可读取的组合状态。任何后续迭代必须先在独立 PR 上重新跑严格导入、领域、桌面和 Release 门禁。

### CameraFeel 原始配置直接合并

影响：非有限值、极端 FOV 或未知字段可以直接进入运行时；信号绑定没有退出解绑，反复加载世界可能留下瞬态引用。

处理：新增纯策略白名单、有限值边界、内部关系约束、确定性解绑和只读快照。

## P1

### 生存压力被全局强制提高

影响：K3 的 70 秒饥饿和 4 秒挨饿伤害会改变所有玩家，尤其不适合儿童与建造型用户；同时农业强化目标本身又有价值。

处理：新增轻松、平衡、挑战三档。默认恢复原有 90/8 节奏，K3 参数保留为平衡档。难度属于全局设置，不进入世界存档。

### 方块碎屑空闲仍参与每帧处理

影响：效果结束后仍保留空 `_process`，材质缓存没有硬上限，与项目预算哲学不一致。

处理：固定 64 节点池、14 粒子/次、128 材质上限；空闲停机并公开诊断。

### 主菜单过度借用 Minecraft 语言

影响：泥土背景、Minecraft 风 splash 和重复的“开始游戏/地图选择”削弱《星的世界》自己的像素科幻品牌。

处理：保留像素斜面组件，但生产背景恢复星云、星座、轨道与行星；操作改为“继续游戏/创建新世界”。

## P2

### 世界装饰仍是生成器内硬编码

K3 的遗迹、仙人掌、花草与晶体已经确定性生成且不破坏旧档，本轮接受。后续应迁移到数据驱动 POI/装饰策略，支持稀有度、结构预算、战利品与任务入口，而不是继续扩张 `world_generator.gd` 的 match 分支。

### 音效事件桥仍需进一步统一

本轮保留已有 `AudioEventBridge`。后续可将脚步、挖掘、进食、落地和奖励统一成有限事件目录，避免领域层知道具体 AudioService 方法。

## 验收矩阵

| 层级 | 内容 |
|---|---|
| 静态 | 策略唯一性、三档难度、粒子预算、品牌组合、测试接线 |
| Headless | 策略边界、难度切换、计时边界、真实 Player CameraFeel、粒子池回收 |
| 相邻 | Settings、Water/Survival、Audio、Player Experience、UI Design、Integration |
| 桌面 | 1024×576 设置页、真实鼠标保存应用、难度即时生效、截图与 JSON |
| 权威 | 全 Runtime、真实桌面玩法矩阵、Windows EXE/PCK 导出与启动 |

## 下一阶段

在本轮收敛通过后，优先建立数据驱动 POI 系统和统一体验事件目录；不在同一批次引入 XP、技能树、附魔或世界高度迁移。
