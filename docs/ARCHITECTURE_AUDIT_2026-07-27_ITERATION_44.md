# Architecture Audit · 2026-07-27 · Iteration 44

## 范围

本轮从主菜单到游戏内 HUD 对生产界面做完整审计，扫描：

- 主菜单、地图选择、设置、存档浏览器和回收站；
- HUD、快捷栏、交互提示、新手引导与 Toast；
- 背包、合成、熔炉、容器、探索日志；
- 暂停、死亡、更新提示与 F3 诊断；
- 1024×576、1280×720 布局测试、真实桌面输入与 Windows Release 门禁；
- `ThemeFactory`、`design_tokens`、重复 StyleBox 和颜色硬编码。

## 发现

### P0 · 主菜单缺少产品级视觉层级

原主菜单是居中大面板与纵向按钮堆叠。开始游戏、地图、存档、设置、更新和退出几乎使用同等视觉权重，无法在第一眼回答“游戏是什么”和“玩家现在应该做什么”。

### P1 · 全部页面使用同质矩形

HUD、教程、弹窗、背包、机器和 F3 大量使用相近的深蓝矩形。由于缺少表面层级、区域标题、状态条和主操作区，功能虽然可用，但整体像开发工具而不是完整游戏。

### P1 · 控件状态存在重复硬编码

多个页面各自创建 StyleBox 或直接修改按钮颜色。选中、交换、危险、成功和键盘焦点没有统一语义，后续新增页面容易继续漂移。

### P1 · 信息密度与优先级不稳定

- HUD 的生命、时间、威胁、快捷栏和提示缺少稳定优先级；
- 设置字段缺少解释和实时数值；
- 地图选择只有文本列表，没有地图简报；
- 存档危险操作与普通操作距离过近；
- F3 两列虽然功能完整，但缺少卡片标题、状态入口和滚动边界。

### P1 · 低分辨率依赖固定尺寸

部分弹窗使用固定尺寸。字体、字段或内容增加后，面板可能在 1024×576 下被最小尺寸重新撑出安全区。探索日志的首次 CI 失败即验证了这一风险。

### P1 · 真实截图覆盖分散

现有各领域拥有大量桌面截图，但没有一条连续旅程从主菜单穿过地图、设置、存档、HUD、弹窗、工作区和 F3，因此整体风格漂移不容易被单个领域门禁发现。

## 决策

1. 建立“星际远征”统一视觉方向；
2. 使用语义化设计令牌取代页面级颜色与间距所有权；
3. 使用 8pt 间距体系、统一圆角、字体层级和控件高度；
4. 暖金只用于单一主操作，冷青用于交互与选择，红色只用于危险与错误；
5. ThemeFactory 成为基础控件状态的唯一所有者；
6. 新增纯 `StarUiKit` 生成标题、徽章、卡片和标准按钮；
7. 主菜单重构为 Hero + Command Deck；
8. 管理页面统一为标题、工具、内容、状态、固定操作结构；
9. 游戏内阻塞界面共享暗幕与响应式弹窗尺寸；
10. 1024×576 下所有长内容必须使用内部滚动而不是扩大窗口；
11. 增加一条真实鼠标/键盘多屏验收，固定输出十张截图；
12. 保持现有领域、存档和输入所有权，不通过 UI 重构复制业务状态。

## 实现

- 扩展 `StarDesignTokens`：语义颜色、空间、圆角、字体、控件高度、阴影和焦点；
- 新增 `StarUiKit`；
- 重构 `ThemeFactory` 的按钮、面板、输入、滚动、进度、提示与焦点状态；
- 主菜单增加程序化星云、星座、轨道和行星背景；
- 地图页变为目录、简报和世界档案；
- 设置页变为四个可解释分组卡，状态与操作固定；
- 存档页建立查询卡、分页、虚拟化卡片列表和危险操作层级；
- HUD 建立生命/时间、威胁、当前物品、快捷栏和提示优先级；
- 背包、合成、容器与探索日志统一为工作区；
- 暂停、死亡与更新提示使用统一 Modal；
- F3 变为运行与运营双卡诊断中心；
- 动画收敛为短时透明度过渡，不改变最终布局矩形。
