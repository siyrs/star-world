# 《星的世界》商业发布质量计划

## 目标

从当前源码重新构建 Windows 游戏，真实运行并覆盖全部正式地图和内容，持续执行“复现—定位—修复—自测—独立 QA 重测”，直到发布验收通过或只剩有实测证据的外部阻塞。

## 执行阶段

1. 只读发现：Git、技术栈、构建/运行/测试、地图与内容、存档/日志、既有 QA 断点。
2. 准备门禁：完成 Developer 方案、QA 测试策略、风险/决策和 readiness 验证。
3. 基线：从当前源码构建，启动新建游戏，采集日志、截图和性能基线。
4. 内容闭环：逐地图正常路径、任务/通关、探索、碰撞、水域、边界、存档、死亡复活和极端操作。
5. 修复闭环：按 P0→P1→P2→P3 修复；每项补回归证据。
6. 长稳与发布验收：重复地图切换/读档、长时间运行、性能前后对比、全量回归、独立 QA。
7. 交付：小提交、完整覆盖矩阵、最终发布报告；不推送、不发布。

## 证据规则

- 每个结论记录分支/commit、命令、时间戳、原始日志/截图/采样路径。
- 过期构建不能代表当前源码；每轮运行先校验源码与 `build/StarWorld.exe` / `build/StarWorld.pck` 时间戳。
- UI 操作结论必须由截图/窗口状态、日志或游戏内可观测状态交叉证明。
- 不用调试传送或存档篡改替代正常玩家路径；调试入口只用于快速到达专项位置。
- `qa/session-state.md` 是中断恢复入口，重要步骤后更新。
