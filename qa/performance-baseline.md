## 1. 本轮纠偏结论

### BUG-PERF-METRIC-001 — qa-passed

**旧版 `1% Low FPS` 已废弃，不得用于发布判定或产品宣传。**

旧脚本把 `Engine.get_frames_per_second()` 的滚动显示值收集后取 1 分位，并把结果命名为 `1% Low FPS`。这不是基于真实逐帧耗时的 1% Low，曾出现“主菜单 1% Low=1 FPS、但逐帧 p95 约 6ms”的内部矛盾。

当前统一定义为：

- `平均 FPS = 1000 / 平均真实帧时`；
- `1% Low FPS = 1000 / 最慢 1% 真实帧的平均帧时`；
- 同时记录帧时 p95、p99、最小/最大帧时；
- 同时记录 60 FPS（16.67ms）和 30 FPS（33.33ms）帧预算超限比例；
- `Engine.get_frames_per_second()` 只保留为 `engine_fps_avg_diagnostic`，不得参与发布判定。

`src/core/frame_performance_metrics.gd` 已提供唯一指标实现；`tests/qa/frame_performance_metrics_regression.gd` 用确定性慢帧夹具验证最慢尾部、无效样本过滤和滚动 FPS 隔离；桌面报告中的每个有效场景还会重新验证 `avg_fps≈1000/frame_ms_avg` 且 `1% Low≤平均 FPS`。

### BUG-PERF-COLUMN-001 — qa-passed

原生成器对同一 `(x,z)` 柱的不同 Y 单元反复计算地表噪声。天空群岛还会在同一柱上反复执行 3×3 岛心搜索；Chunk 生成和邻接面查询会继续放大重复工作。

当前实现：

- 缓存不可变的 `surface_height` 与 `sky_strength`；
- 默认容量 8,192，最小 256，硬上限 32,768；
- 确定性 FIFO 淘汰；
- FIFO 账本按阈值压缩，值表和顺序表都不会无限增长；
- Profile 或 Seed 变化时强制失效；
- 玩家方块覆盖、Chunk 快照和其他可变世界状态不进入该缓存；
- 运行时 streaming diagnostics 暴露命中、未命中、存储、淘汰、容量和真实计算次数；
- 同一版本内可关闭缓存，对比缓存前后生成结果。

## 2. 确定性热点基准

固定条件：`sky_islands`、Seed `112358`、完整生成一个 16×16×64 Chunk，共 16,384 个方块查询；缓存开启和关闭在同一进程、同一代码版本内执行。

| 指标 | 缓存关闭 | 缓存开启 | 结果 |
|---|---:|---:|---:|
| 总耗时 | 345,428 μs | 116,287 μs | 约 **2.97×** 加速 |
| 地表高度真实计算 | 16,424 | 256 | 约 **64.2×** 减少 |
| 天空岛强度真实计算 | 17,418 | 256 | 约 **68.0×** 减少 |
| 生成方块差异 | — | 0 / 16,384 | 完全一致 |
| 缓存条目 | 0 | 256 | 低于 8,192 容量 |
| 淘汰 | 0 | 0 | 单 Chunk 无淘汰 |

树冠逻辑会在 Chunk 边缘向外查询最多两格，因此专项回归使用 20×20 的有界柱足迹作为上限，而不是错误要求所有场景永远恰好 256 条。五个正式 Profile 均已执行缓存开关前后的方块序列逐项对比。

## 3. GitHub 桌面采集环境边界

专项桌面 Job 的实际环境是：

- Windows Server 2025；
- Godot 4.7 stable；
- `gl_compatibility`；
- 1280×720；
- GitHub 托管 Runner；

- 音频设备不可用，自动回退 dummy driver。

因此本 Job 可以证明：

- 五个 Profile 的真实桌面采集链路可运行；
- schema v2 指标定义和数据一致性正确；
- 真实 streaming/cache 遥测被写入报告；
- 外部 Working Set/Private Bytes 采样有效；
- 运行过程没有 crash、fatal、parse error 或泄漏。

它**不能证明目标玩家电脑的最终 FPS 达标**。下表数值只用于审计软件渲染路径和回归趋势，不得直接写成最低/推荐硬件性能。
