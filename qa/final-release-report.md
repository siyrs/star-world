## 2. 证据等级合同

所有 QA 文档、问题状态和发布结论必须使用以下等级，不得跨级推断：

| 等级 | 证据类型 | 可以证明 | 不能证明 |
|---|---|---|---|
| E0 | 静态文件、注册表、配置检查 | 内容被声明、资源可加载 | 内容可玩或体验正常 |
| E1 | 纯策略、生成器、离线数据扫描 | 规则确定性、地图特征可能存在 | 玩家能够正常到达、碰撞正确、视觉合理 |
| E2 | 真实运行时中的服务、状态或事务 | 服务可工作、状态可保存 | 玩家通过正式输入完成了流程 |
| E3 | 生产场景 + 正式输入 + 真实物理/UI/交互 | 玩家可在被覆盖路径实际操作并完成断言 | 未覆盖内容、完整视觉体验和长期主观手感 |
| E4 | 最终导出程序的桌面操作、截图/录屏和独立人工复审 | 最终包体中的可见布局、反馈、连贯性和主观体验 | 所有随机 Seed 与无限程序化空间 |

“完整探索”至少需要 E3 的区域、连续路线、边界、兴趣点和特殊环境覆盖，并对关键视觉与手感提供 E4 证据。单独的 E0/E1/E2 不得标记为完整探索；生产场景 desktop acceptance 也不得被冒充为最终导出程序人工 E4。

### 3.4 JSON metadata 类型漂移修复

首轮真实修理旅程中，53 项断言只有两项精确结构比较失败：

- `world.json` 与保存前背包不完全相等；
- 完整重载后的背包与保存前不完全相等。

单独的耐久、名称、材料和修理台断言全部正确，因此问题不是数据丢失，而是结构类型漂移。根因是 JSON 数值边界会把 `durability`、`magazine_rounds` 等整数 metadata 读回为浮点数值形态；旧背包 canonical 规则只处理空 metadata，没有规范已知数值类型。

修复方案：

- `InventoryService` 新增集中 `_canonicalize_metadata()`；
- `serialize()` 和 `deserialize()` 共用同一规则；
- `durability`、`magazine_rounds` 的 int/float 合法数值统一恢复为 int；
- 非法的已知整数 metadata 被剔除；
- 未知 metadata 原样保留，不破坏未来扩展；
- 空 metadata 继续省略；
- 畸形 metadata 不污染运行时；
- 相邻槽位的有效 metadata 保持独立。

canonical 回归由 13 项扩展到 **21 checks**，新增真实 `JSON.stringify → JSON.parse_string` 边界、旧浮点整数值、非法已知数值和无关 metadata 保留验证。修复后，合成 78 项和修理 53 项完整重载均保持精确结构相等。

## 7. 剩余工作的优先顺序

下一阶段应继续按照“一个关键领域一个真实玩家闭环”的方式推进，不再用服务存在性代替玩家体验：

1. 机器：供料、等待、收货、失败、Chunk 卸载、返回菜单和跨会话重载；
2. 畜牧/牧场：父母、幼崽、冷却、产物计时、拾取和完整活体重载；
3. 农业：从空背包获取材料到锄地、播种、灌溉/施肥、成长、收获和重载；
4. 床与重生：玩家放床、设置出生、保存、死亡、返回菜单、重载和回床；
5. 探索/里程碑：正常寻找材料、制作仪器、到达地点、失败地图反馈和全部里程碑；
6. 五图连续路线：出生点到关键区域、边界、狭窄区、水下、地下、高空和脱困；
7. 最终导出 E4：真实 Windows 包体中的完整操作、截图/录屏和独立人工体验；
8. 真实目标硬件：最低/推荐配置的同场景性能与严格 120 分钟长稳。
